## Overview

The TvetGreen Skill Hub app has been configured as a Progressive Web App, allowing users to install it on their devices (desktop and mobile) and use it like a native application. The implementation follows Expo's recommended approach for single-page applications.

## What is a PWA?

A Progressive Web App (PWA) is a website that can be:
- **Installed** on the user's device (desktop or mobile)
- **Used offline** (with service worker support)
- **Launched** like a native app (standalone mode, no browser UI)
- **Accessible** from the home screen/app launcher

PWAs provide a native app-like experience while being built with web technologies.

## Implementation Details

### 1. App Configuration (`app.json`)

The PWA configuration is defined in the `web` section of `app.json`:

```json
{
  "expo": {
    "web": {
      "bundler": "metro",
      "output": "single",
      "favicon": "./assets/images/favicon.png",
      "name": "TvetGreen Skill Hub",
      "shortName": "TvetGreen",
      "lang": "en",
      "scope": "/",
      "themeColor": "#000000",
      "backgroundColor": "#ffffff",
      "display": "standalone",
      "orientation": "portrait",
      "startUrl": "/",
      "crossorigin": "use-credentials",
      "preferRelatedApplications": false
    }
  }
}
```

**Key Configuration Options:**
- `display: "standalone"` - Opens the app without browser UI
- `themeColor` - Color of the browser/device UI when the app is installed
- `backgroundColor` - Background color shown during app launch
- `startUrl` - The URL the app opens to when launched
- `scope` - Defines which URLs the PWA can access

### 2. HTML Template (`public/index.html`)

Expo uses a custom HTML template for web builds. This template was created using:

```bash
npx expo customize public/index.html
```

The template includes:
- Standard HTML structure with Expo's React Native Web reset styles
- **Manifest link**: `<link rel="manifest" href="/manifest.json" />`
- **Apple mobile web app meta tags** for iOS Safari support
- Placeholders that Expo replaces during build (`%WEB_TITLE%`, `%LANG_ISO_CODE%`)

**Important Meta Tags:**
```html
<!-- Link the PWA manifest file -->
<link rel="manifest" href="/manifest.json" />

<!-- Apple mobile web app support -->
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="default" />
<meta name="apple-mobile-web-app-title" content="TvetGreen" />
```

### 3. Manifest File (`public/manifest.json`)

The manifest file describes the app's metadata and installation behavior:

```json
{
  "short_name": "TvetGreen",
  "name": "TvetGreen Skill Hub",
  "description": "TVET Green learning platform - Access courses and educational content",
  "icons": [
    {
      "src": "favicon.ico",
      "sizes": "64x64 32x32 24x24 16x16",
      "type": "image/x-icon"
    },
    {
      "src": "logo192.png",
      "type": "image/png",
      "sizes": "192x192"
    },
    {
      "src": "logo512.png",
      "type": "image/png",
      "sizes": "512x512"
    }
  ],
  "start_url": ".",
  "scope": "/",
  "display": "standalone",
  "orientation": "portrait",
  "theme_color": "#000000",
  "background_color": "#ffffff",
  "lang": "en"
}
```

**Manifest Properties:**
- `short_name` - Name shown on home screen (limited space)
- `name` - Full app name
- `icons` - Array of icon files in different sizes
- `display` - How the app appears when launched (`standalone`, `fullscreen`, `minimal-ui`)
- `start_url` - Entry point when app is launched
- `theme_color` - Browser/device UI color
- `background_color` - Splash screen background

### 4. Icon Files

Three icon files are required in the `public/` directory:

- `favicon.ico` - Automatically generated by Expo from `web.favicon` in `app.json`
- `logo192.png` - 192x192 pixel icon (minimum recommended)
- `logo512.png` - 512x512 pixel icon (recommended for high-DPI displays)

These icons are copied from `assets/images/icon.png` during setup.

### 5. Build Script (`scripts/add-pwa-manifest.js`)

A post-build script ensures all PWA files are copied to the `dist` directory:

```javascript
// Copies manifest.json, logo192.png, and logo512.png from public/ to dist/
```

This script runs automatically after `expo export --platform web` completes.

## How It Works

### Build Process

1. **Expo Export**: Running `pnpm run build:web` executes:
   ```bash
   expo export --platform web && node scripts/add-pwa-manifest.js
   ```

2. **HTML Generation**: Expo reads `public/index.html` and:
   - Replaces placeholders (`%WEB_TITLE%` → "TvetGreen Skill Hub")
   - Adds theme-color meta tag from `app.json`
   - Adds favicon link
   - Injects the JavaScript bundle reference
   - Outputs to `dist/index.html`

3. **File Copying**: The post-build script:
   - Copies `manifest.json` from `public/` to `dist/`
   - Copies `logo192.png` and `logo512.png` to `dist/`
   - Ensures all PWA assets are available in the build output

4. **Manifest Processing**: Browsers read `manifest.json` to:
   - Determine if the app can be installed
   - Get app name, icons, and display preferences
   - Configure the installed app's behavior

### Installation Flow

1. **User visits the website** in a supported browser (Chrome, Edge, Safari)
2. **Browser detects PWA** by reading the manifest file
3. **Install prompt appears**:
   - Desktop: Install button in address bar
   - Mobile: "Add to Home Screen" prompt or browser menu option
4. **User installs** the app
5. **App appears** on home screen/app launcher with the configured icon
6. **App launches** in standalone mode (no browser UI) when opened

### Browser Support

- **Chrome/Edge** (Desktop & Android): Full PWA support
- **Safari** (iOS): Limited support, uses Apple-specific meta tags
- **Firefox**: Basic PWA support
- **Opera**: Full PWA support

## Building and Testing

### Development

During development, run:

```bash
pnpm run dev
```

Then press `w` to open in web browser. The app works normally, but PWA features are only available in production builds.

### Production Build

1. **Build the web app**:
   ```bash
   pnpm run build:web
   ```

2. **Serve the build** (for local testing):
   ```bash
   npx serve dist
   ```
   Or use any static file server pointing to the `dist` directory.

3. **Test PWA installation**:
   - Open the served URL in Chrome/Edge
   - Look for the install icon in the address bar (desktop)
   - Check "Application" tab in DevTools → "Manifest" section
   - Verify icons and metadata are correct

### Testing Checklist

- [ ] Manifest file is accessible at `/manifest.json`
- [ ] Icons load correctly (check Network tab)
- [ ] App name appears correctly in install prompt
- [ ] App opens in standalone mode after installation
- [ ] Theme color matches browser UI
- [ ] App icon appears on home screen/launcher
- [ ] App launches to correct start URL

### Chrome DevTools Testing

1. Open Chrome DevTools (F12)
2. Go to **Application** tab
3. Check **Manifest** section:
   - Verify all icons load
   - Check for any errors
   - Verify display mode is "standalone"
4. Check **Service Workers** (if implemented):
   - Verify registration
   - Check cache status

## Troubleshooting

### Manifest Not Found (404)

**Problem**: Browser can't find `/manifest.json`

**Solutions**:
- Ensure `public/manifest.json` exists
- Verify the post-build script copied it to `dist/`
- Check that the HTML includes: `<link rel="manifest" href="/manifest.json" />`
- Ensure the web server serves files from the `dist` directory root

### Icons Not Loading

**Problem**: Icons show as broken or default

**Solutions**:
- Verify `logo192.png` and `logo512.png` exist in `public/`
- Check that files were copied to `dist/` after build
- Ensure icon paths in `manifest.json` are relative (e.g., `"logo192.png"` not `"/logo192.png"`)
- Check file permissions and web server configuration

### Install Button Not Appearing

**Problem**: Browser doesn't show install prompt

**Solutions**:
- Ensure you're using HTTPS (or localhost for development)
- Check that `display: "standalone"` is set in manifest
- Verify manifest is valid JSON (use a JSON validator)
- Check browser console for manifest errors
- Ensure start_url and scope are correctly configured

### App Opens in Browser Instead of Standalone

**Problem**: Installed app opens with browser UI

**Solutions**:
- Verify `display: "standalone"` in `manifest.json`
- Check that `app.json` has `web.display: "standalone"`
- Clear browser cache and reinstall the app
- Some browsers may require additional configuration

### Theme Color Not Applied

**Problem**: Browser UI doesn't use the configured theme color

**Solutions**:
- Verify `themeColor` in `app.json` matches `theme_color` in manifest
- Check that meta tag exists: `<meta name="theme-color" content="#000000" />`
- Some browsers may not support theme color
- Clear cache and reinstall
